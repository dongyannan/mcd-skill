# 麦麦商旅美食专家 · mcd-biztravel-gourmet

> 出差在外，**吃什么是你最不想花脑子的事** —— 交给它。

一个基于 **麦当劳中国 MCP Server** 的商旅场景助手。你只说「去哪、几个人、什么时候到」，它把四餐按餐补排好、把客情那杯咖啡冷热搭好、把一天的账结好。

**省心 > 省事 > 省钱。** 前三件事做到了，钱自然就省了 —— 但我们从不用「省钱」当卖点，因为出差人最缺的是**注意力**，不是那几块钱。

---

## 它解决什么

出差的一天，你要为吃饭做的决策是这样的：

| 时点 | 你要想的 | 它替你答的 |
| --- | --- | --- |
| 06:20 高铁站 | 还有 25 分钟检票，来不来得及买？买到能不能带上车？ | **先回答「来不来得及」**，来不及就给落地后方案 |
| 11:00 刚落地 | 我 11:30 到会场，几点下单外卖才不会凉？ | **按到达时间倒推下单时点** |
| 15:00 见客户 | 4 个人，买几杯？冷的热的怎么配？算谁的账？ | **按人数配单 + 冷热搭配 + 单列业务招待** |
| 21:30 回酒店 | 今天花了多少？还剩多少额度？我今天钠是不是超标了？ | **一句话给答案**，并推荐低卡低钠方案 |
| 22:40 睡前 | 明天报销又要翻手机找订单…… | **报销流水一键生成** |

## 四个真实剧本

### 剧本 A · 高铁一日往返（北京南 → 上海虹桥）

```text
06:20 北京南站  「还有 25 分钟检票，要能拿着上车吃，别辣的」
      → 站内自提可行性判断 + 忌口过滤 + 叠券
      → 距检票 25 分钟"可行"，若排队超 12 分钟自动切"落地后"方案

11:12 浦东会场  「11:30 到会场，叫个外送到会场，预算 60」
      → 建临时收货地址 → 按到达时间倒推下单（10:40 下单，11:12 送达）
      → >50 元档丰富组合（官方搭配规则）

15:00 客户公司  「4 杯咖啡，要热的，别太苦」
      → 5 杯（4 人 + 1 备损）· 冷热搭配 · 品类不重复
      → 单列「业务招待」科目，不占当日餐补

21:30 酒店加班  「今天还剩多少钱？叫个夜宵，清淡点」
      → 今日餐补已用 / 剩余 + 当日钠摄入汇总 → 低卡低钠方案

22:40 收尾      「出个报销清单」
      → 差旅 ¥90.50 未超标 ✅ ｜ 业务招待另计 ¥63.00
```

### 剧本 B · 飞机出差（**主动不出「登机前的一餐」**）

这是本项目的**减法设计**，也是最容易被记住的一点：

1. 机场（尤其安检后）**不一定有**麦当劳；即使有也常在远机位 / 不同出发区，**走错就误机**；
2. 值机 → 安检 → 登机的时间**完全不可控**，点餐风险远高于高铁站；
3. 机场餐选择少、时间窗口还紧 —— **「落地再吃」比「机场硬凑」更省心**。

所以识别到「出行方式 = 飞机」时，它**不生成登机前餐方案**，把第一餐前移到**落地后**；可选探测机场店，有则给极速自提，没有就直说「机场没有麦当劳，落地再吃」。

> 别的助手让你在机场瞎凑合，它知道机场那顿**不值得赌**。

### 剧本 C·D · 其余高频场景

展会泡一天（把午餐送到展位）｜一周三城连轴（按城市自动分账）｜团队出差（团餐通道 + 人均 AA）｜红眼航班落地（低卡夜宵 + 次日早餐预置）｜客户派对团建（主题派对预订链路）。

## 两个差异化机制

### 一、动态忌口引擎 —— 忌口随「当时当地」变

普通点餐助手的忌口是**死标签**：设了「去冰」就永远去冰。可现实是 —— **北京 10 月要热饮，深圳 8 月必须加冰**。

三层结构，动态层优先但不能覆盖硬禁忌：

| 层级 | 内容 | 可被覆盖？ |
| --- | --- | --- |
| **L1 硬禁忌** | 过敏原、宗教约束、明确不吃（香菜） | ❌ 永不可覆盖 |
| **L2 静态偏好** | 「我一般去冰」「少糖」 | ✅ 可被 L3 覆盖 |
| **L3 动态层** | 气温 / 气候带 / 时段 / 当日营养反馈 | ✅ 优先级最高 |

实测输出（**同一份档案，两座城，两个答案**）：

```bash
$ mcd-biztravel prefs --city 北京 --temp 12 --hour 8 --meal breakfast
  气温 12℃（来自 --temp 实传）· 华北
  冰量 → 去冰（优先热饮）
  - 档案偏好：正常冰（L2，可被动态层覆盖）
  - 动态层（气温）：气温 12℃ < 15℃ → 去冰
  - ⚠️ 动态层覆盖静态偏好：正常冰 → 去冰
  - 动态层（时段）：早餐时段 → 优先热饮

$ mcd-biztravel prefs --city 深圳 --temp 32 --hour 15 --meal afternoon
  气温 32℃（来自 --temp 实传）· 华南
  冰量 → 加冰
  - ⚠️ 动态层覆盖静态偏好：正常冰 → 加冰
```

**没有天气 API 怎么办？** 不假装知道天气 —— 支持 `--temp 31` 实传；没传就用**内置的 30 城 × 12 月气候基线**估算，并在输出里明确标注「按气候基线估算」。**断网也能动态调整。**

### 二、招待搭配引擎 —— 招待不是「买 N 杯一模一样的」

| # | 规则 | 说明 |
| --- | --- | --- |
| **R1** | **冷热搭配** | 按气温定冷热比（≥28℃ → 冷:热 ≈ 3:2；<22℃ → 全热）；**永远至少留 1 杯热饮** |
| **R2** | **品类去重** | 同一 SKU 不超过总数的 60%（5 杯 → 同款最多 3 杯） |
| **R3** | **轻重搭配** | 含餐食时：主食 + 小食 + 蔬菜/玉米杯 各至少一 |
| **R4** | **备损** | ≥4 人时多备 1 份（防泼洒 / 临时加人） |

外加两条「懂行」的细节：**至少 1 杯无咖啡因**（照顾不喝咖啡的人）、**至少 1 杯常温**（照顾肠胃敏感）。

## 安装

**零依赖**：只用 Python 标准库，不需要 `pip install` 任何东西。

```bash
git clone https://github.com/dongyannan/mcd-skill.git
cd mcd-skill

python3 -m venv .venv && source .venv/bin/activate
pip install -e .          # 可选，装了就能直接用 mcd-biztravel 命令
```

**拿 Token**：打开 <https://open.mcd.cn/mcp> → 手机号登录 → 右上角「控制台」→「激活」→ 同意协议 → 一键复制 Token。

```bash
export MCD_MCP_TOKEN="你的Token"
```

> ⚠️ Token 只从环境变量读，**绝不落盘、绝不进仓库**。`.gitignore` 已挡掉 `.env` / `mcp-config.json` / `*.local.json`。

**第一次用**：`mcd-biztravel profile init` 生成档案（`~/.mcd_biztravel/profile.json`），改成你自己的城市、餐补标准、忌口。

## 使用

```bash
# 0. 连通性自检
mcd-biztravel doctor

# 1. 看动态忌口怎么结算（不改任何东西）
mcd-biztravel prefs --city 深圳 --temp 32 --hour 15

# 2. 配餐方案（核心）
mcd-biztravel plan --city 北京 --meal breakfast --budget 20 --temp 12 --price

# 3. 客户招待配单
mcd-biztravel hospital --city 深圳 --people 4 --temp 32 --price

# 4. 报销流水
mcd-biztravel report --date today --csv ~/Desktop/报销.csv

# 5. 差旅档案
mcd-biztravel profile show
mcd-biztravel profile set --hard-avoid 香菜,花生 --ice 常温 --budget lunch=60,dinner=80

# 6. 直通调用任意 MCP 工具（默认只读）
mcd-biztravel mcp --tool query-my-account
```

## 安全与合规

| 措施 | 说明 |
| --- | --- |
| **默认只读** | 7 个写操作工具（`create-order` / `cancel-order` / `auto-bind-coupons` / `draw-lottery` / `mall-create-order` / `party-order-create` / `delivery-create-address`）**不加 `--yes` 一律拦截**，先打印「将要发生什么」 |
| **Token 不落盘** | 只从环境变量读；日志、输出、仓库里都不会出现 |
| **输出打码** | 手机号（`138****5678`）、身份证号、长订单号自动脱敏 |
| **不做医疗建议** | 营养数据仅作参考展示，措辞遵官方声明 |

## 已知限制（诚实说明）

- `query-nearby-stores(searchType=2)` 按城市/位置搜索需要**真实定位上下文**，无定位时服务端返回 `600058`；当前可用路径是**收藏门店**（`searchType=1`）。
- 麦当劳菜单里「可乐 / 雪碧 / 红茶」等 SKU **本身不带冷热属性**，冷热属于**商品特制选项**；因此招待配单会在输出里明确提示需要在下单时改特制，而不是假装已经选好了热饮。
- 菜单不区分时段（早餐菜单在晚间仍会返回），因此早餐配餐暂按全日菜单处理。
- 单位不一致：`query-meals` 的价格是**元**（字符串），`calculate-price` 是**分**（整数）—— 已在代码里统一换算。
